# Prism 项目规划

## 1. 项目概述

**项目名称**：Prism  
**产品定位**：面向企业公关与品牌团队的桌面端危机公关推演工具  
**核心隐喻**：棱镜折射——同一事件经由不同公众视角折射，呈现截然不同的舆论光谱。Prism 让决策者在正式发声前，透视每一种策略可能引发的舆论走向。

### 1.1 价值主张
企业危机回应的细微差异会导致截然不同的舆论走向。Prism 提供一个低成本的数字推演环境，使决策者能够在真实发声前，观察并比较不同策略在舆论场中的演化结果。

### 1.2 开发约束
- 开发周期：2 周
- 团队规模：6 人
- 产品形态：桌面应用
- 目标平台：macOS 为主，兼容 Windows
- 开发方式：AI 辅助开发

---

## 2. 产品定义

### 2.1 目标用户
企业公关部门、品牌管理部门、危机应对小组成员。

### 2.2 使用场景
1. 企业遭遇舆情危机，需评估不同回应声明的效果。
2. 品牌团队准备发布可能引发争议的声明，需提前预判公众反应。
3. 管理层需要在内部会议前获得数据化的策略对比依据。

### 2.3 核心流程

新建项目 → 录入危机事件 → 配置回应策略 → 运行多智能体仿真 → 查看舆论演化 → 对比策略结果 → 导出评估报告

支持从历史项目回溯，调整参数后重新推演。

## 3. 设计系统

Prism 的设计语言围绕"光谱"与"折射"展开——从棱镜的几何切割感中提取视觉元素，同时保持现代桌面应用的专业克制。

### 3.1 设计原则
- **光谱感**：用渐变色阶与透叠隐喻多视角折射，替代扁平纯色。
- **清晰层级**：信息结构明确，主次分明，关键数据以微动效引导视线。
- **几何裁剪**：卡片与图表采用轻微斜切角（2px chamfer）替代传统圆角，呼应棱镜切面。
- **克制装饰**：不使用纹理、材质、拟物元素；活力来自色彩与排版节奏，而非装饰堆砌。
- **跨平台一致**：QSS 统一样式，macOS 与 Windows 上呈现一致。

### 3.2 色彩系统
棱镜折射光谱为意象基础，主色调取自可见光谱的端点延伸。

| 用途 | 色值 | 说明 |
|------|------|------|
| 窗口背景 | `#F8F9FC` | 冷白基调，通透明亮 |
| 侧边栏背景 | `#1A1D2E` | 深靛基底，营造景深感 |
| 卡片背景 | `#FFFFFF` | 纯白内容区 |
| 主文字 | `#1B1C23` | 近黑，高可读性 |
| 次要文字 | `#7C7E8A` | 灰紫中调 |
| 侧边栏文字 | `#A8ABC0` | 深底上的中明度文字 |
| 边框 / 分隔线 | `#E4E6EE` | 浅灰蓝 |
| 强调色-主 | `#5B5FEF` | 靛紫，主按钮 / 选中态 / 图表主线 |
| 强调色-辅 | `#7C3AED` | 紫罗兰，hover 态 / 数据高亮 |


### 3.4 组件规范
- 窗口：8px 外圆角，无标题栏文字仅图标按钮。
- 侧边栏：固定宽度 240px，深色背景，图标 + 文字导航，选中态左侧 3px 强调色竖线 + 半透明底色。
- 卡片：白色背景，6px 圆角 + 左上角 2px chamfer 切角，1px 边框，悬停时轻微上浮阴影（4px blur, 8% 透明度）。
- 主按钮：6px 圆角，强调色背景 + 白色文字，hover 加深 10%。
- 次按钮：6px 圆角，浅灰背景 + 强调色文字 + 1px 强调色边框。
- 输入框：6px 圆角，聚焦时强调色 2px 边框 + 外发光。
- 图表：细线（1px），清晰刻度，策略 A/B 分别使用对应渐变色，网格线极淡。
- 进度/加载：细线脉冲动画，强调色。

## 4. 技术方案

### 4.1 架构
Prism 为单体桌面应用，基于 PySide6 实现全部交互与业务逻辑。选择 PySide6 而非 PyQt6 的原因是其 LGPL 许可更友好，且 API 与 PyQt6 几乎完全兼容。敏感数据本地处理，无需服务器部署。

```
┌─────────────────────────────────────────────┐
│                  PySide6 UI                 │
├──────────────┬──────────────────────────────┤
│  页面路由     │   widgets / charts / styles  │
├──────────────┴──────────────────────────────┤
│              业务逻辑层                        │
├──────────────┬──────────────┬───────────────┤
│  仿真引擎     │  LLM Client  │  Report Gen   │
├──────────────┴──────────────┴───────────────┤
│              SQLite 数据层                    │
├─────────────────────────────────────────────┤
│           OpenAI / Anthropic API            │
└─────────────────────────────────────────────┘
```

### 4.2 技术栈
| 用途 | 技术 | 备注 |
|------|------|------|
| 桌面 UI | PySide6 | LGPL 许可，与 PyQt6 API 兼容 |
| 业务逻辑 | Python 3.11+ | |
| LLM 调用 | openai SDK + anthropic SDK | 支持 fallback：任一厂商不可用时切换 |
| 数据存储 | SQLite | 单文件数据库，便携 |
| 数据可视化 | pyqtgraph | 原生 Qt 集成，性能优于嵌入 matplotlib |
| 报告导出 | WeasyPrint（PDF） + QTextBrowser（应用内预览） | 图表通过 pyqtgraph 导出 PNG 嵌入报告；应用内直接查看，PDF 用于存档分享 |
| 配置管理 | python-dotenv + keyring | API Key 使用系统钥匙串存储 |
| 打包分发 | PyInstaller | macOS .app + Windows .exe |

### 4.3 安全设计
- API Key 优先使用系统钥匙串（macOS Keychain / Windows Credential Manager），`.env` 仅作开发兜底。
- `.env` 中仅存储非敏感配置（默认模型、重试次数等），API Key 字段留空由应用内首次配置引导填写。
- 仿真缓存与历史数据全部存储在本地 SQLite，不上传任何数据至第三方。
- `.gitignore` 排除 `.env`、`*.db`、`dist/`、`build/`。

## 5. 功能范围

### 5.1 项目入口 & 历史管理
- 新建推演项目 / 从历史记录继续
- 项目列表：名称、创建时间、最近一次仿真状态、快捷操作（继续/删除）
- 项目设置：LLM 厂商选择、模型选择、温度参数

### 5.2 危机事件录入
- 事件标题与涉及行业（下拉 + 自定义）
- 事件背景描述（富文本，支持分段）
- 企业现有声明稿（可选）
- 初始热度（1-100 滑块）与公众情绪基线（-1.0 ~ 1.0 滑块）

### 5.3 策略配置
- 支持 2~4 种回应策略
- 每种策略包含：名称、声明稿全文、计划发布时间（模拟小时偏移）
- 策略对比预览：并排展示差异

### 5.4 多智能体仿真
- 自动生成 8 个固定类型 Agent（详见 §6）
- 每种策略独立运行 8~12 轮仿真（可配置）
- 每轮代表 4 小时模拟时间（共 32~48 小时推演窗口）
- 输出热度曲线、情绪分布、支持率变化与关键事件时间线

### 5.5 仿真控制
- 启动 / 暂停 / 中止仿真
- 实时显示当前轮次进度与 Agent 发言流
- 仿真中断后可从断点恢复（自动保存检查点）

### 5.6 结果可视化
- 策略对比面板：热度 / 情绪 / 支持率双曲线叠加图
- 策略评估雷达图（6 维度：公信力、传播性、可控性、风险指数、舆论韧性、信息一致性）
- 关键事件时间线（横向时间轴 + 事件卡片）
- Agent 发言摘录（按策略分组，高亮关键转折言论）

### 5.7 评估报告
- 策略对比与推荐（量化评分 + 文字解读）
- 风险提示（高影响事件标记）
- 优化建议（Prompt 驱动的策略改进方向）
- 应用内预览：QTextBrowser 渲染完整报告（图表、文字、时间线）
- 导出：PDF（用于存档与分享）

## 6. 仿真模型

### 6.1 Agent 类型（8 个）
| 类型 | 立场 | 影响力 | 活跃度 | 特征 |
|------|------|--------|--------|------|
| 普通消费者 A | opposing | 1.0 | 高 | 情绪驱动，易被舆论裹挟 |
| 普通消费者 B | neutral | 0.8 | 中 | 理性观望，依赖事实 |
| 普通消费者 C | supportive | 0.6 | 低 | 品牌忠诚用户，倾向维护企业 |
| 媒体人 / KOL | opposing | 2.5 | 高 | 初始观望，随热度升高转为对立，追求流量，倾向放大争议 |
| 业内人士 | opposing | 1.5 | 中 | 专业视角，质疑企业操作 |
| 监管观察者 | neutral | 2.0 | 低 | 仅对合规问题反应，其他话题沉默 |
| 竞品方 | opposing | 1.8 | 中 | 伺机借势攻击，但避免直接露骨 |
| 企业官方发言人 | supportive | 3.0 | 按策略触发 | 唯一可控 Agent，按声明稿输出 |

### 6.2 Agent 属性
```python
class Agent:
    id: int
    name: str
    role: str                    # 角色标签
    stance: str                  # "opposing" | "neutral" | "supportive"
    base_stance: str             # 初始立场（用于复位）
    influence: float             # 单次发言对世界状态的影响力权重
    activity: float              # 每轮被激活的概率（0~1）
    emotion: float               # 当前情绪值（-1.0 ~ 1.0，负=愤怒/焦虑，正=冷静/乐观）
    trust: float                 # 对企业的信任度（0~1）
    active_hours: List[int]      # 活跃时段（模拟小时，如 [8, 9, ..., 22]）
    profile: str                 # 角色画像（Prompt 中的 System Message）
    memory: List[str]            # 最近 N 轮的记忆摘要（滑动窗口）
```

### 6.3 世界状态
```python
class WorldState:
    round: int
    simulated_hour: int          # 累计模拟小时
    heat: float                  # 热度（0~100）
    sentiment: float             # 整体情绪（-1.0 ~ 1.0）
    support_rate: float          # 企业支持率（0~1）
    key_events: List[KeyEvent]   # 本轮触发的关键事件
    agent_states: Dict[int, AgentSnapshot]  # 每个 Agent 本轮快照
```

### 6.4 单轮仿真流程
```
1. 时间推进 → simulated_hour += 4
2. 激活判定 → 根据 active_hours + activity 概率筛选本轮活跃 Agent
3. 策略触发 → 若 simulated_hour >= 策略发布时间，官方发言人发布声明稿
4. 上下文构建 → 向每个激活 Agent 注入：
   - 世界状态摘要（热度、情绪、支持率）
   - 上一轮触发的 KeyEvent（首轮为空）
   - 该 Agent 最近 memory
   - 官方声明（若已发布）
5. Agent 生成反应 → LLM 返回结构化 JSON（情绪变化、信任变化、发言内容、传播意图）
6. 状态更新 → 汇总所有 Agent 输出，更新 WorldState：
   - heat += Σ(influence × 传播意图系数)
   - sentiment 加权平均
   - support_rate 加权平均
7. 关键事件检测 → 若 heat / sentiment 跨越阈值，触发 KeyEvent
8. 检查点写入 → 写入 SQLite，支持中断恢复
```

### 6.5 Agent 间交互（传播模型）
- 每轮结束后，高影响力 Agent 的发言会以衰减系数（0.3）扩散至所有 Agent 的 memory
- KOL 的发言具有二次传播效应（额外 0.15 系数）
- 同立场 Agent 之间信任修正：若多数 opposing Agent 情绪恶化，neutral Agent 有概率向 opposing 偏移

### 6.6 关键事件
| 事件类型 | 触发条件 | 影响 |
|---------|---------|------|
| 媒体跟进报道 | heat > 60 且 KOL 发言含"调查""进一步"等关键词 | heat +10, sentiment -0.15 |
| 监管介入信号 | 监管观察者连续 2 轮发言提及"合规""监管" | heat +15, trust 全体 -0.1 |
| 竞品借势攻击 | heat > 50 且竞品方本轮被激活 | heat +5, sentiment -0.1 |
| 内部员工爆料 | 随机（5% 概率，heat > 40 后启用） | heat +20, support_rate -0.15 |
| 话题登顶热搜 | heat > 80 | heat +10（封顶 100）, 全体 activity ×1.5 |
| 舆情自然降温 | heat > 30 且连续 3 轮无 KeyEvent | heat -5, sentiment +0.05 |

## 10. 错误处理与容错

### 10.1 LLM 调用
- 单次调用超时：30s
- 失败重试：最多 3 次，指数退避（2s / 4s / 8s）
- JSON 解析失败：尝试修复常见格式错误，仍失败则丢弃本轮该 Agent 输出，沿用上一轮状态
- 厂商 fallback：OpenAI 不可用时自动切换 Anthropic，反之亦然；均不可用时回退至 Demo 模式（使用预置的静态仿真数据保证演示不中断）

### 10.2 仿真运行
- 每轮结束后自动写 SQLite 检查点
- 中断恢复：启动时检查是否存在未完成的仿真，提示用户继续或放弃
- 单轮卡死：若某轮超过 120s 未完成，强制跳过并记录警告

### 10.3 数据完整性
- SQLite 使用 WAL 模式，防止写入中断导致数据库损坏
- 项目删除为软删除（标记 deleted_at），支持恢复

## 11. 风险与应对

| 风险 | 概率 | 影响 | 应对措施 |
|------|------|------|---------|
| LLM 输出不稳定 | 高 | 高 | JSON Schema 约束 + 重试机制 + 输出修复 + Demo 数据预缓存 |
| API 成本过高 | 中 | 中 | 限制 8 Agent / 10 轮 / 2 策略 ≈ 160 次调用；优先使用低价模型（GPT-4o-mini / Claude Haiku） |
| 两周无法完成 | 中 | 高 | 严格 MVP，Week 1 必须跑通单策略闭环；非核心功能（多策略/报告）可降级为静态展示 |
| 仿真结果不逼真 | 中 | 中 | 真实案例调优 Prompt；产品定位明确为"辅助推演"而非"预测" |
| 跨平台 UI 不一致 | 低 | 中 | 统一 QSS，macOS + Windows 双平台分别验证；使用系统原色避免硬编码 |
| WeasyPrint 环境依赖 | 中 | 中 | 提前在开发机配置 pango；备选：应用内预览始终可用，PDF 为加分项 |
| PySide6 打包体积大 | 低 | 低 | PyInstaller 精简模式；Demo 阶段可不打包 |

### 11.1 关键假设
- 团队成员具备 Python 基础，至少一人熟悉 PySide6/PyQt。
- 能够获得稳定可用的 LLM API Key（OpenAI 或 Anthropic 至少其一）。
- 小组能够保持每日同步与高频协作。

## 附录 A：Agent ↔ 模拟时间映射规则

由于模拟每轮为 4 小时，`active_hours` 与轮次的关系：

- 第 0 轮 = simulated_hour 0-3（深夜，仅官方发言人可能活跃）
- 第 1 轮 = simulated_hour 4-7（凌晨）
- 第 2 轮 = simulated_hour 8-11（上午，多数 Agent 活跃）
- 第 3 轮 = simulated_hour 12-15（午间）
- 以此类推

激活判定：若 Agent 的 `active_hours` 列表与当前轮次覆盖的 4 小时窗口有交集，则该 Agent 进入激活候选池；再以 `activity` 概率最终决定是否激活。

## 附录 B：策略评估雷达图维度定义

| 维度 | 含义 | 计算方式 |
|------|------|---------|
| 公信力 | 策略发布后企业可信度变化 | trust 均值变化 |
| 传播性 | 信息扩散的速度与广度 | heat 峰值 / 达到峰值的轮次 |
| 可控性 | 舆论走势与企业预期的偏差 | |actual_sentiment - expected_sentiment| |
| 风险指数 | 策略引发的负面影响强度 | KeyEvent 触发次数 × 严重度加权 |
| 舆论韧性 | 舆论从负面回归中性的速度 | sentiment 恢复速率 |
| 信息一致性 | Agent 之间对事件认知的差异度 | Agent 发言主题的聚类离散度 |
