# Prism 项目规划

## 1. 项目概述

- **项目名称**：Prism
- **产品定位**：面向供应链管理者的桌面端供应链决策推演工具
- **核心隐喻**：棱镜折射——供应链中某一行为体的决策如同一束光，经过上下游各节点的折射，产生截然不同的全局影响。Prism 让决策者在实际执行前，透视每一项决策对整个供应链的连锁反应。

### 1.1 价值主张
供应链中单个节点的决策（如调价、囤货、切换供应商）往往引发不可预见的连锁反应。Prism 提供一个低成本的数字推演环境，使管理者能够在真实决策前，观察决策在供应链网络中经行为体互动折射演化的结果，获取数据化的决策参考。

### 1.2 开发约束
- 产品形态：桌面应用
- 目标平台：macOS 为主，兼容 Windows
- 开发方式：AI 辅助开发

---

## 2. 产品定义

### 2.1 目标用户
供应链管理团队、运营总监、物流规划师、采购与库存管理人员。

### 2.2 使用场景
1. 企业面临原材料价格波动，需评估不同采购策略对整条供应链的影响。
2. 物流团队准备调整配送路线或仓储布局，需提前预判交付时效与成本变化。
3. 管理层需评估自产 vs 外包决策在供应链各环节的后果（可通过多次仿真对比）。

### 2.3 核心流程

首页（项目列表）→ 工作区（供应链搭建 → 行为体决策 → 仿真 → 结果）→ 导出报告

支持从历史项目回溯，调整参数后重新推演。

## 5. 功能范围

### 5.1 项目列表
- 新建推演项目 / 打开历史项目
- 项目卡片：名称、状态（草稿/运行中/已中断/已完成）、创建日期
- 右键删除（软删除）

### 5.2 供应链搭建（Step 01）
- 供应链名称、行业类型（下拉 + 自定义）
- 供应链节点定义：供应商 → 制造商 → 分销商 → 零售商，支持添加/删除节点
- 各节点初始参数：库存水平、交货周期、成本结构、产能上限
- 文档导入（PDF / Word / Markdown / TXT），自动分块存入知识库（RAG）；已入库分块按来源文档可见，支持一键清空
- AI 分析导入文档：自动抽取并填写名称/行业/背景/节点/基线参数，用户可核对修改后再保存

### 5.3 行为体性格配置（Step 02）
- 7 类行为体的性格调整：决策倾向（激进/保守/协作/防御）、活跃度、影响力、角色画像（persona）
- 种子事件配置：0~3 条世界干预（内容 + 注入周期），在对应周期注入行动信息流并沿链路传播
- AI 生成行为体配置：基于场景由 LLM 生成全部行为体性格与种子事件，可手动微调
- 配置随供应链场景保存（project.scenario_json 的 agents_config 与 seed_events）

### 5.4 多行为体仿真（Step 03）
- 7 个固定类型行为体（详见第 6 节）
- 单一世界多轮仿真（默认 12 轮，设置页可调 4~24），每轮代表 1 个供应链周期
- 行为体经行动信息流互相感知、显式回应，演化由互动推动
- LLM 配置在全局「设置」页统一管理（见 5.7），本页仅展示当前生效厂商
- 实时显示库存/成本/服务水平/利润率指标、行为体行动与回应摘要
- 启动 / 暂停 / 重置控制
- QThread 后台运行，不阻塞 UI
- 仿真完成自动生成报告（含 LLM 叙述式综合分析，失败自动降级为纯公式报告）

### 5.5 演化分析（Step 04）
- 深色结论横幅：项目名/生成时间、综合建议结论、概述、末态指标与首末变化（涨跌按语义着色）
- AI 综合分析：LLM 生成的演化解读、风险归因与可执行建议，支持按需重新生成并落库
- 指标演化曲线：库存/成本/服务水平/利润率/交付延迟折线图（各系列归一化，含图例）
- 演化结果评估：六维雷达图（成本控制/交付稳定性/库存健康度/风险抵御/协同效率/可执行性）
- 风险与建议：公式规则检测结果
- 演化过程泳道图：行为体 × 周期的行动色块矩阵（按行动类型着色，点击查看详情，关键事件周期标红）
- 明细数据：按周期的指标快照表（默认折叠）
- 导出 Markdown（含 AI 综合分析章节）

### 5.6 评估报告
- 单世界演化评估与建议
- 风险提示
- 应用内终端日志
- 导出 Markdown

### 5.7 设置（全局配置）
- 与「项目列表」「工作区」平级的独立设置页
- LLM 配置：7 组厂商预设（Anthropic / DeepSeek / Kimi / OpenAI / 通义千问 / 智谱 / 自定义，按品牌名字母序），各厂商 API Key/URL/模型独立记忆，切换不丢失
- 当前生效厂商（LLM_ACTIVE_VENDOR）全局统一：Step1/2/3/4 的所有 AI 功能共用
- 仿真参数：仿真轮次（4~24）、行为体决策温度（0~1，较低更稳定、较高发言更多样）
- 调用参数：请求超时（5~180 秒，思考型模型可调大）、重试次数（0~5）
- 显式「保存配置」持久化到 .env 并即时生效；「测试连接」验证配置可用性

## 6. 仿真模型

### 6.1 行为体类型（7 个）
| 类型 | 角色 | 影响力 | 活跃度 | 特征 |
|------|------|--------|--------|------|
| 原材料供应商 | 上游 | 1.0 | 中 | 受价格波动影响，可能延迟交付 |
| 制造商 | 核心 | 2.5 | 高 | 协调上下游，产能与排产决策中心 |
| 分销商 | 中游 | 1.5 | 中 | 库存缓冲，受需求波动冲击 |
| 零售商 | 下游 | 1.8 | 高 | 直面消费者，对价格和库存最敏感 |
| 物流服务商 | 支撑 | 1.2 | 中 | 运输时效与成本的关键变量 |
| 消费者 | 末端 | 2.0 | 高 | 需求驱动，受价格与服务水平影响 |
| 监管机构 | 外部 | 2.0 | 低 | 仅对合规与安全事件反应 |

### 6.2 单轮仿真流程
1. 周期推进 → cycle += 1
2. 种子事件注入 → 命中当前周期的 seed_events 写入行动信息流（当轮即可被观察）
3. 激活判定 → 根据活跃度筛选本轮参与的行为体
4. 观察构建 → 从行动信息流（ActionFeed）为每个行为体生成个性化观察：供应链邻居（按节点链路上下游判定）的全部行动 + 全链高影响力（≥1.5）行动；同一轮的行动互相不可见，行为体只能看到更早轮次的行动
5. 决策执行 → 各行为体依据自身性格与观察做出响应，并显式回应相关行动（支持/反对/跟随/反制）
6. 行为体生成反应 → LLM 返回结构化 JSON（行动类型 action_type、回应对象 reaction_to、库存变化、成本变化、交付延迟等），行动类型受角色行动空间约束，越权降级为 maintain；reaction_to 仅允许其他行为体名称或 none，多目标取首个合法值，节点名/世界事件等非法值降级为 none 并记 warning
7. 状态更新 → 汇总所有行为体输出，更新供应链全局状态
8. 关键事件检测 → 跨越阈值触发 KeyEvent（断供、爆仓、价格战等）
9. 行动写回 → 本轮行动以 ActionRecord 形式写入共享信息流，供后续轮次观察（反应链跨轮形成）
10. 检查点写入 → 写入 SQLite

### 6.3 行为体互动模型

- **共享信息流（ActionFeed）**：每轮行动结构化记录（行为体、行动类型、指标影响、原话、回应对象），是所有互动的中介；行为体之间不直接通信
- **种子事件（seed_events）**：用户在 Step 02 配置的世界干预，在指定周期以"世界事件"身份写入信息流（全链广播），行为体观察到后反应，干预沿链路传播——对应 MiroFish 的 initial_posts 机制
- **观察层**：邻居行动全部可见，非邻居行动仅高影响力（≥1.5）广播可见；节点链路缺失时使用兜底主链（供应商→制造商→分销商→零售商→消费者）判定上下游；同一行为体相邻轮次内容高度相似（相似度 ≥0.7）时旧条目折叠为「持续中」，抑制发言复读
- **行动空间**：`maintain / adjust_supply / adjust_price / adjust_capacity / expedite_logistics / reduce_orders / shift_demand / intervene`，每类行为体仅有子集（如监管只能 maintain/intervene）
- **同步更新语义**：同轮行为体互不可见，反应链跨一轮形成（与 MiroFish/OASIS 一致）
- 检查点恢复时信息流从空重建，首轮观察降级为"暂无"，随后续轮次恢复

### 6.4 关键事件
| 事件类型 | 触发条件 | 影响 |
|---------|---------|------|
| 原材料断供 | 供应商连续 2 轮交货延迟 > 0.5 | 库存 -20, 成本 +15, 延迟 +2, 服务 -5%, 利润 -8% |
| 仓储爆仓 | 全链库存水平 > 90 | 成本 +10, 延迟 -1, 利润 -3% |
| 价格战触发 | 零售商利润变化为负且全链利润率 < 0 | 库存 -5, 服务 +5%, 利润 -5% |
| 监管介入 | 监管机构连续 2 轮标记风险 | 成本 +15, 延迟 +1, 服务 -3%, 利润 -10% |
| 需求激增 | 消费者单轮库存变化 < -8 | 库存 -15, 延迟 +1.5, 服务 -8%, 利润 +5% |

> 无事件轮次指标会缓慢回归基线（引擎内置的静默恢复机制），不作为关键事件呈现。

## 9. 错误处理与容错

### 9.1 LLM 调用
- 单次调用超时：默认 30s（设置页可调 5~180s，见 §5.7）
- 失败重试：指数退避（默认 3 次，设置页可调 0~5）
- JSON 解析失败：尝试修复常见格式错误
- 全链路统一使用设置页的生效厂商；仅当生效厂商未配置 Key 时，回退 OPENAI/ANTHROPIC 环境变量链

### 9.2 仿真运行
- 每轮结束后自动写 SQLite 检查点
- 中断恢复：支持从检查点继续

### 9.3 数据完整性
- SQLite WAL 模式
- 项目软删除（deleted_at），支持恢复

## 10. 风险与应对

| 风险 | 应对 |
|------|------|
| LLM 输出不稳定 | JSON Schema 约束 + 重试 + 输出修复 |
| API 成本过高 | 单次仿真调用量 ≈ 轮次 × 行为体数（默认 12×7=84 次）；优先使用低价模型 |
| 仿真结果不逼真 | 定位为"辅助推演"而非"预测" |
| 跨平台 UI 不一致 | QSS 统一样式，macOS + Windows 分别验证 |
