# Prism 项目规划

## 1. 项目概述

- **项目名称**：Prism
- **产品定位**：面向供应链管理者的桌面端供应链决策推演工具
- **核心隐喻**：棱镜折射——供应链中某一行为体的决策如同一束光，经过上下游各节点的折射，产生截然不同的全局影响。Prism 让决策者在实际执行前，透视每一种方案对整个供应链的连锁反应。

### 1.1 价值主张
供应链中单个节点的决策（如调价、囤货、切换供应商）往往引发不可预见的连锁反应。Prism 提供一个低成本的数字推演环境，使管理者能够在真实决策前，观察并比较不同方案在供应链网络中的演化结果，获取数据化的决策建议。

### 1.2 开发约束
- 产品形态：桌面应用
- 目标平台：macOS 为主，兼容 Windows
- 开发方式：AI 辅助开发

---

## 2. 产品定义

### 2.1 目标用户
供应链管理团队、运营总监、物流规划师、采购与库存管理人员。

### 2.2 使用场景
1. 企业面临原材料价格波动，需评估不同采购策略对整条供应链的影响。
2. 物流团队准备调整配送路线或仓储布局，需提前预判交付时效与成本变化。
3. 管理层需对比自产 vs 外包决策在供应链各环节的差异化后果。

### 2.3 核心流程

首页（项目列表）→ 工作区（供应链搭建 → 行为体决策 → 仿真 → 结果）→ 导出报告

支持从历史项目回溯，调整参数后重新推演。

## 4. 技术方案

### 4.1 架构
Prism 为单体桌面应用，基于 PySide6 实现全部交互与业务逻辑。

```
┌──────────────────────────────────────────┐
│              PySide6 UI                  │
│        home / process / styles           │
├──────────────────────────────────────────┤
│              业务逻辑层                    │
├────────────┬────────────┬────────────────┤
│  仿真引擎   │ LLM Client │  Report Gen    │
├────────────┴────────────┴────────────────┤
│            SQLite 数据层                  │
├──────────────────────────────────────────┤
│        OpenAI / Anthropic API            │
└──────────────────────────────────────────┘
```

### 4.2 技术栈
| 用途 | 技术 | 备注 |
|------|------|------|
| 桌面 UI | PySide6 | LGPL 许可 |
| 业务逻辑 | Python 3.11+ | |
| LLM 调用 | openai SDK + anthropic SDK | 支持 fallback |
| 数据存储 | SQLite | 单文件数据库，WAL 模式 |

| 配置管理 | python-dotenv | API Key 通过 .env 或页面输入 |
| 文档解析 | pypdf + python-docx | RAG 文档导入 |

## 5. 功能范围

### 5.1 项目列表
- 新建推演项目 / 打开历史项目
- 项目卡片：名称、状态（草稿/运行中/已完成）、创建日期
- 右键删除（软删除）

### 5.2 供应链搭建（Step 01）
- 供应链名称、行业类型（下拉 + 自定义）
- 供应链节点定义：供应商 → 制造商 → 分销商 → 零售商，支持添加/删除节点
- 各节点初始参数：库存水平、交货周期、成本结构、产能上限
- 文档导入（PDF / Word / Markdown / TXT），自动分块存入知识库（RAG）

### 5.3 行为体决策配置（Step 02）
- 支持 2~4 种决策方案
- 每种方案包含：名称、涉及的行为体、决策内容（如调价幅度、库存策略、供应商切换）
- 预设 2 组默认决策模板
- 保存到 StrategyRepository

### 5.4 多行为体仿真（Step 03）
- 7 个固定类型行为体（详见第 6 节）
- 每种决策方案独立运行 8~12 轮仿真
- 每轮代表 1 个供应链周期
- LLM 配置：7 组厂商预设（OpenAI / Anthropic / DeepSeek / 通义千问 / Kimi / 智谱 / 自定义）
- API Key 支持 .env 或页面输入
- 实时显示库存/成本/服务水平/利润率指标、行为体响应摘要
- 启动 / 暂停 / 重置控制
- QThread 后台运行，不阻塞 UI
- 仿真完成自动生成报告

### 5.5 结果分析（Step 04）
- 推荐决策方案 + 执行摘要
- 方案对比表格（库存/成本/交付时效/服务水平/利润率/韧性）
- 六维评分（成本控制/交付稳定性/库存健康度/风险抵御/协同效率/可执行性）
- 导出 Markdown

### 5.6 评估报告
- 方案对比与推荐
- 风险提示
- 应用内终端日志
- 导出 Markdown

## 6. 仿真模型

### 6.1 行为体类型（7 个）
| 类型 | 角色 | 影响力 | 活跃度 | 特征 |
|------|------|--------|--------|------|
| 原材料供应商 | 上游 | 1.0 | 中 | 受价格波动影响，可能延迟交付 |
| 制造商 | 核心 | 2.5 | 高 | 协调上下游，产能与排产决策中心 |
| 分销商 | 中游 | 1.5 | 中 | 库存缓冲，受需求波动冲击 |
| 零售商 | 下游 | 1.8 | 高 | 直面消费者，对价格和库存最敏感 |
| 物流服务商 | 支撑 | 1.2 | 中 | 运输时效与成本的关键变量 |
| 消费者 | 末端 | 2.0 | 高 | 需求驱动，受价格与服务水平影响 |
| 监管机构 | 外部 | 2.0 | 低 | 仅对合规与安全事件反应 |

### 6.2 单轮仿真流程
1. 周期推进 → cycle += 1
2. 激活判定 → 根据活跃度筛选本轮参与的行为体
3. 决策执行 → 各行为体按当前方案做出响应
4. 行为体生成反应 → LLM 返回结构化 JSON（库存变化、成本变化、交付延迟等）
5. 状态更新 → 汇总所有行为体输出，更新供应链全局状态
6. 关键事件检测 → 跨越阈值触发 KeyEvent（断供、爆仓、价格战等）
7. 检查点写入 → 写入 SQLite

### 6.3 关键事件
| 事件类型 | 触发条件 | 影响 |
|---------|---------|------|
| 原材料断供 | 供应商连续 2 轮交货延迟 > 阈值 | 制造商库存 -20%, 成本 +15% |
| 仓储爆仓 | 分销商/零售商库存 > 容量上限 | 持有成本 +10%, 交付时效 -1 周期 |
| 价格战触发 | 零售商利润率为负且竞争行为体激活 | 全链利润率 -5%, 需求 +20% |
| 监管介入 | 监管机构连续 2 轮标记风险 | 合规成本 +15%, 运营暂停概率 10% |
| 需求激增 | 消费者需求环比 > 50% | 全链交付压力 +30%, 库存消耗加速 |
| 自然恢复 | 连续 3 轮无 KeyEvent | 各指标缓慢回归基线 |

## 9. 错误处理与容错

### 9.1 LLM 调用
- 单次调用超时：30s
- 失败重试：指数退避
- JSON 解析失败：尝试修复常见格式错误
- 厂商 fallback：OpenAI / Anthropic 自动切换

### 9.2 仿真运行
- 每轮结束后自动写 SQLite 检查点
- 中断恢复：支持从检查点继续

### 9.3 数据完整性
- SQLite WAL 模式
- 项目软删除（deleted_at），支持恢复

## 10. 风险与应对

| 风险 | 应对 |
|------|------|
| LLM 输出不稳定 | JSON Schema 约束 + 重试 + 输出修复 |
| API 成本过高 | 每方案 160 次调用上限；优先使用低价模型 |
| 仿真结果不逼真 | 定位为"辅助推演"而非"预测" |
| 跨平台 UI 不一致 | QSS 统一样式，macOS + Windows 分别验证 |
